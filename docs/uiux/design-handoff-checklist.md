# 設計交付檢核表

## MVP 設計目標

| 目標 | 判斷標準 |
|---|---|
| 降低陌生人合購的不信任 | 使用者能在申請前理解團主、規則、PM 幣代管與退款條件 |
| 讓複雜狀態變成清楚待辦 | 成員與團主都能一眼知道現在輪到誰做什麼 |
| 減少私下對帳與私訊成本 | 付款、帳號資訊、聊天室、通知與申訴都留在平台內 |
| 支援一人多角色 | 同一使用者能自然切換我的訂閱與群組管理 |
| 讓例外可被處理 | 拒絕、退出、逾期、續訂失敗、申訴、裁定都有可理解路徑 |

## Wireframe 範圍

| 優先級 | 畫面/流程 | 低保真需涵蓋 |
|---|---|---|
| P0 | 探索群組與群組詳情 | 卡片資訊階層、篩選、訪客鎖定狀態、申請入口 |
| P0 | 申請加入與 PM 幣儲值 | 餘額不足、代管說明、同意條款、申請成功/失敗 |
| P0 | 我的訂閱 | 審核進行中、招募中、填寫/提取資訊、待啟用服務、確認進行中、服務進行中、歷史 |
| P0 | 群組管理 | 申請審核、額滿鎖定、資訊收集、啟用、收款、續訂、歷史 |
| P0 | 問題回報與申訴 | 成員回報、團主處理、平台介入、裁定結果 |
| P1 | 建立群組 | 4 步驟表單、即時預覽、驗證錯誤 |
| P1 | 通知中心 | 分類、歷史、點擊導向、未讀狀態 |
| P1 | 訊息中心 | 群組聊天室、DM、系統通知、附件預覽 |
| P1 | 帳號/信用/評價/偏好 | 個人資料、信用分數說明、評價列表、隱私與主題設定 |
| P2 | 管理後台 | 概覽、申訴裁定、平台回報、帳號管理、系統訊息 |
| P2 | 法律文件 | 條款、隱私、免責聲明可讀性 |

## Prototype 必測路徑

| 路徑 | 必測任務 |
|---|---|
| 訪客探索到申請 | 從首頁或探索頁找到群組，登入後回到群組並送出申請 |
| 餘額不足 | 點擊申請時發現 PM 幣不足，完成儲值後繼續申請 |
| 團主審核到額滿 | 團主接受申請，群組額滿後鎖定 |
| 邀請型服務啟用 | 成員填 email 或邀請碼，團主啟用，成員確認 |
| 共用帳密服務啟用 | 團主鎖定時填帳密，成員提取資訊並確認 |
| 申訴 | 成員回報問題，團主處理或升級平台，管理員裁定 |
| 續訂 | 團主選擇續訂成員，餘額檢查成功或失敗 |
| 通知導向 | 點擊通知後正確跳到對應頁面並開啟群組或面板 |

## 內容策略檢核

| 類型 | 規則 |
|---|---|
| 狀態標籤 | 優先使用使用者懂的語言，例如「成員填寫中」「待啟用服務」「確認進行中」 |
| 付款文案 | 使用「PM 幣」「代管」「退款」「撥款」，避免讓使用者以為是私下轉帳 |
| 等待文案 | 必須說明等待誰：團主、成員、平台、系統 |
| 服務帳號資訊 | 依共享機制使用不同動詞：填寫、提取、邀請碼、共用帳密 |
| 危險操作 | 先說後果，再要求確認；不要只寫「確定嗎」 |
| 空狀態 | 同時說明目前沒有什麼，以及下一步能做什麼 |
| 錯誤 | 說明可修正原因；併發或過期資料要提示重新整理 |

## 可用性測試計畫

| 項目 | 建議 |
|---|---|
| 受測者 | 至少 3 位潛在成員、2 位可能開團者；若可行再加 1 位只看後台的維運者 |
| 測試形式 | 30 到 45 分鐘遠端或面對面任務測試，搭配 think aloud |
| 任務 1 | 找到一個想加入的群組並說明為什麼信任或不信任它 |
| 任務 2 | 在餘額不足情境下完成儲值並送出申請 |
| 任務 3 | 以團主身分審核申請、鎖定群組並找出下一步 |
| 任務 4 | 在服務有問題時提出回報，說明錢目前會怎麼處理 |
| 任務 5 | 從通知進入指定群組任務 |
| 觀察指標 | 是否看懂代管、是否看懂下一步、是否找得到待辦、是否誤解狀態 |

## 量化觀察指標

| 指標 | 用途 |
|---|---|
| 探索到群組詳情開啟率 | 衡量卡片資訊是否足夠吸引點擊 |
| 群組詳情到申請送出率 | 衡量信任與申請門檻是否合理 |
| 申請表單放棄率 | 找出 PM 幣、規則同意或資訊不足造成的阻力 |
| 團主審核時間 | 看團主是否能快速理解申請與做決策 |
| 鎖定到全員資訊完成時間 | 衡量帳號資訊流程是否清楚 |
| 確認期問題回報率 | 分辨服務品質問題與 UX 誤解 |
| 通知點擊後完成率 | 衡量通知是否真的能帶使用者完成任務 |
| 續訂成功率 | 衡量到期提醒、餘額準備與續訂流程 |

## 無障礙與響應式檢核

| 檢查項 | 標準 |
|---|---|
| 鍵盤操作 | 主要按鈕、Modal、Drawer、選單、表單皆可用鍵盤抵達與關閉 |
| 焦點管理 | 開啟 Modal 時焦點進入內容，關閉後回到觸發點 |
| 色彩對比 | 狀態徽章不能只靠顏色；文字對比符合可讀性 |
| 表單錯誤 | 欄位錯誤靠文字說明，不只改邊框顏色 |
| 小螢幕 | 卡片、按鈕與長文字不可水平溢出 |
| 觸控目標 | 手機主要操作至少維持容易點擊的尺寸 |
| 動畫 | 動畫只輔助理解，不阻擋任務；尊重系統減少動態偏好 |

## 上線前 UX 檢核

- 訪客不登入也能理解平台價值並看到可加入供給。
- 申請前能看懂 PM 幣代管與退款規則。
- 我的訂閱與群組管理都能清楚顯示下一步待辦。
- 每個群組狀態都有明確空狀態、錯誤狀態與不可逆操作確認。
- 通知能正確導向對應頁面與 Modal。
- 手機、平板、桌機三種導覽模式都能完成 P0 任務。
- 敏感帳號資訊有權限限制、遮罩或風險提醒。
- 申訴與裁定路徑有足夠證據與結果通知。
