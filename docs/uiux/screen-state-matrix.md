# 畫面狀態與互動矩陣

這份文件補足 UI/UX 前期製作中常見的 screen inventory、state matrix 與互動規格。狀態轉換的商業規則以 [群組狀態機](../flows/group-state-machine.md) 為主；本文件聚焦「畫面上應該怎麼呈現」。

## 全域 UI 狀態

| 狀態 | 觸發 | 畫面規則 |
|---|---|---|
| 未登入 | 無有效會員 session | 可看首頁、探索、條件搜尋與法律文件；受保護動作顯示鎖定提示並引導登入 |
| 已登入 | 一般會員 session 有效 | 顯示會員主導覽、PM 幣、通知、訊息、使用者選單 |
| 管理員登入 | 管理員 session 有效 | 只進入 `/admin` 後台，不與一般會員導覽混用 |
| 載入中 | 首次讀資料、換頁、重新整理 | 使用骨架或最小 loading，不應清空已可用資料造成閃爍 |
| 空狀態 | 列表無結果或無歷史紀錄 | 提供下一步動作，例如探索群組、建立第一個群組、調整篩選 |
| 過期資料 | 輪詢或點擊時發現狀態變更 | 不靜默替換使用者正在看的清單；用提示讓使用者決定是否刷新 |
| 失敗 | API 錯誤、驗證不通過、併發衝突 | 保留已輸入內容，顯示可理解原因與下一步 |
| 不可逆操作 | 退出、解散、確認服務、裁定 | 使用確認對話，重要操作加倒數或明確二次確認 |

## 主要畫面盤點

| 畫面/元件 | 主要使用者 | 回答的問題 | 主操作 | 空/錯誤狀態 |
|---|---|---|---|---|
| 首頁 `/` | 訪客、回訪使用者 | PartyMatch 是什麼，為何可信 | 前往探索、建立/加入 CTA | 精選群組不足時仍保留產品說明 |
| 探索群組 `/explore` | 訪客、成員 | 現在有哪些可加入群組 | 分類篩選、條件搜尋、開詳情、收藏 | 無符合分類時引導調整篩選 |
| 群組詳情 Modal | 訪客、申請人、成員、團主 | 這個群組可不可以加入/我下一步要做什麼 | 申請、取消申請、退出、填寫資訊、確認、回報問題 | 群組不存在或已不可見時提示並關閉/返回列表 |
| 條件搜尋 Modal | 訪客、成員 | 如何精準找到合適群組 | 選服務、設定條件、查看推薦結果 | 無結果時引導回探索列表 |
| 建立群組 Modal | 團主 | 如何開一個可招募群組 | 選服務、選方案、設定、預覽送出 | 送出失敗時移除暫存結果並保留可修正提示 |
| 我的訂閱 `/my-subscriptions` | 成員 | 我加入/申請的群組現在到哪一步 | 開群組、填寫/提取資訊、確認服務、看歷史 | 無訂閱時引導探索群組 |
| 群組管理 `/manage-groups` | 團主 | 我建立的群組哪些需要處理 | 審核、鎖定、啟用、續訂、結束、看歷史 | 無群組時引導建立第一個群組 |
| 我的收藏 `/favorites` | 成員 | 我之前收藏哪些群組 | 開詳情、取消收藏 | 無收藏時引導探索 |
| 訊息中心 Modal | 已登入使用者 | 我跟誰需要溝通 | 群組聊天室、私訊、上傳圖片 | 無對話時顯示空狀態 |
| 通知中心 Drawer | 訪客、會員 | 有哪些待辦或系統訊息 | 篩選、排序、點擊導向、標記已讀 | 無通知時依登入狀態顯示不同文案 |
| PM 幣 Modal | 已登入使用者 | 我的餘額是否足夠 | 模擬儲值、查看紀錄 | 交易失敗時保留輸入 |
| 帳號/偏好 Modal | 已登入使用者 | 我的資料、信用、評價與偏好 | 編輯資料、主題/隱私、停用帳號 | 操作失敗時不關閉 Modal |
| 管理後台 `/admin` | 管理員 | 平台有哪些待處理事件 | 裁定申訴、處理回報、發訊息、帳號管理 | 無案件時顯示明確空狀態 |
| 法律文件 | 所有人 | 使用條款、隱私與聲明 | 閱讀 | 不需要互動 CTA |

## 群組狀態矩陣

| 實作狀態 | 使用者看見的狀態 | 團主主操作 | 成員主操作 | UX 注意事項 |
|---|---|---|---|---|
| `recruiting` | 招募中 | 審核申請、移除已加入成員、解散群組 | 申請加入；已加入者等待額滿或可退出 | 探索頁只顯示招募中且有名額的群組；團主自己的群組不應出現在自己的探索結果 |
| `full` | 等待鎖定 | 鎖定群組、移除成員、解散群組 | 已加入者等待鎖定；鎖定前可退出 | 團主卡片顯示「尚未鎖定」，成員卡片顯示「等待鎖定」，避免成員誤以為自己卡住 |
| `pending_confirmation` | 成員填寫中/帳號提取中 | 查看成員資訊、回報帳號問題；資訊齊全後可進入待啟用服務 | 邀請型服務填寫資訊；共用帳密型提取並確認 | 文案需依 `sharingMethod` 區分「填寫」與「提取」 |
| `pending_activation` | 待啟用服務 | 啟用服務、設定下次扣款日 | 等待團主啟用 | 清楚呈現等待對象是團主，避免成員誤以為自己還有事要做 |
| `confirming` | 確認進行中 | 追蹤成員確認、處理問題、必要時調整扣款日 | 確認服務正常，或回報問題 | 這是信任關鍵期，確認與回報入口都要容易找到 |
| `disputed` | 問題處理中 | 回覆問題、標記處理完成、升級客服介入 | 補充問題、等待處理；非申訴者可按確認期邏輯理解 | 需要顯示資金凍結與目前處理方，降低焦慮 |
| `active` | 服務進行中 | 查看收款、處理平台回報、到期前續訂或結束 | 使用服務、等待續訂提醒、查看下次扣款日 | 到期前 7 天可強化續訂提醒 |
| `cancelled` | 已解散 | 查看歷史 | 查看歷史與退款結果 | 不再顯示一般操作，只保留歷史脈絡 |
| `ended` | 已結束服務 | 查看管理紀錄、評價 | 查看訂閱紀錄、評價 | 訊息入口不再作為主要操作 |

## 申請狀態矩陣

| 申請狀態 | 使用者文案 | 成員可做 | 團主可做 |
|---|---|---|---|
| `pending` | 審核進行中 | 取消申請並退款 | 接受或拒絕 |
| `approved` | 申請通過 | 等待群組額滿/鎖定 | 視群組狀態管理成員 |
| `rejected` | 未通過 | 回探索找其他群組 | 無 |
| `cancelled` | 已取消 | 可重新申請 | 知道申請人已取消 |
| `left` | 已退出 | 回探索或重新申請 | 名額釋出 |
| `removed` | 已移出 | 查看通知與退款 | 名額釋出 |

## Modal 與面板分層

| 層級 | 元件 | 開啟方式 | 設計規則 |
|---|---|---|---|
| 全域工作 Modal | 建立群組、條件搜尋、訊息中心、PM 幣、帳號設定 | 側邊欄、Drawer、事件 | 開啟時關閉其他同層面板，避免重疊失控 |
| 群組詳情 Modal | 一般群組詳情、成員視角群組操作 | URL query 或事件 | 可深連結，關閉時移除 `group` query |
| 團主管理 Modal | 團主視角 HostGroupView | 群組管理卡片或通知 | 與群組詳情互斥，同一時間只呈現一個群組工作區 |
| 子流程 Modal | 申請、填寫服務資訊、啟用、續訂、申訴、評價 | 群組工作區內觸發 | 只處理單一任務，送出後回到原群組上下文 |
| 通知 Drawer | 通知中心 | 全域通知按鈕或事件 | 點擊通知先標記已讀，再導向並開啟目標上下文 |

## 內容與文案狀態

| 情境 | 文案重點 |
|---|---|
| 金流 | 說明「PM 幣代管」「退款」「撥款」的目前狀態，避免使用轉帳式語言 |
| 敏感資訊 | 說明帳號資訊只對有權限的人可見，必要時提示不要截圖轉傳 |
| 鎖定功能 | 未登入時使用「登入後可使用」，避免讓訪客以為功能壞掉 |
| 等待中 | 指明等待對象：等團主審核、等其他成員加入、等成員填寫、等團主啟用 |
| 錯誤 | 用業務語言說明原因，例如名額已滿、餘額不足、狀態已改變 |
| 不可逆操作 | 明確說明後果，例如解散會退款給所有成員且不可恢復 |

## 響應式行為

| 裝置情境 | 導覽規則 |
|---|---|
| 桌機且支援 hover | 使用可展開側邊欄；右側保留通知、儲值、主題、訊息浮動按鈕 |
| 觸控裝置或無 hover | 使用左側 Drawer；使用者選單在 Drawer 內以二層面板呈現 |
| 手機 | 主要任務按鈕固定在易觸及位置；長列表保持單欄；Modal 內容需避免水平溢出 |
| iPad/平板 | 視為觸控導覽，不單靠螢幕寬度切桌機側邊欄 |

## 可用性風險清單

| 風險 | 需要特別檢查 |
|---|---|
| 群組狀態與按鈕不一致 | 每次改狀態機都檢查群組卡片、詳情、我的訂閱、群組管理 |
| 成員不知道下一步 | 所有處理中狀態都要顯示明確待辦者 |
| 團主漏看待辦 | 管理卡片、通知未讀數、待處理徽章需一致 |
| 金流語意不清 | 申請、退款、撥款、續訂都要顯示 PM 幣數量與去向 |
| Modal 層級過深 | 子流程結束後回到原上下文，不把使用者丟回列表頂部 |
| 通知過度打擾 | 影響清單的更新使用手動刷新提示，非關鍵事件不要自動重排畫面 |
