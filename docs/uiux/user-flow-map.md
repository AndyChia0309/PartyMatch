# 使用者流程圖

這份文件整理跨角色、跨頁面的主流程。單一功能的細節仍以 `docs/flows` 下的文件為主。

## 端到端核心流程

```mermaid
flowchart LR
  A[訪客進入首頁或探索頁] --> B[瀏覽群組或使用條件搜尋]
  B --> C{找到合適群組}
  C -->|否| B
  C -->|是| D{是否已登入}
  D -->|否| E[登入或註冊]
  D -->|是| F[開啟群組詳情]
  E --> F
  F --> G{PM 幣餘額足夠}
  G -->|否| H[儲值 PM 幣]
  H --> F
  G -->|是| I[送出加入申請並代管扣款]
  I --> J[團主審核申請]
  J -->|拒絕或申請取消| K[退款回個人餘額]
  K --> B
  J -->|接受| L[等待群組額滿]
  L --> M[團主鎖定群組並開啟聊天室]
  M --> N{服務共享機制}
  N -->|邀請型| O[成員填寫服務帳號資訊]
  N -->|共用帳密型| P[團主提供帳密 成員提取確認]
  O --> Q[團主啟用服務]
  P --> Q
  Q --> R[成員確認服務]
  R -->|正常| S[服務進行中]
  R -->|有問題| T[申訴或問題處理]
  T --> U{解決方式}
  U -->|雙方自行解決| R
  U -->|管理員裁定| S
  S --> V{到期}
  V -->|續訂| M
  V -->|結束| W[移入歷史紀錄 可選擇補評價]
```

## 訪客到會員流程

```mermaid
flowchart TD
  A[進入首頁] --> B[理解 PartyMatch 價值主張]
  A --> C[直接進入探索群組]
  B --> C
  C --> D[使用分類篩選或條件搜尋]
  D --> E[開啟群組詳情]
  E --> F{想收藏/申請/聯絡}
  F -->|否| C
  F -->|是| G[導向登入或註冊]
  G --> H[完成驗證後回到原任務]
  H --> I[收藏或申請加入]
```

設計重點：

- 訪客可以先使用探索與條件搜尋，讓產品價值先被看見。
- 被鎖定的功能要明確告知「登入後可使用」，並提供前往登入的動作。
- 登入後應盡量回到原本被中斷的任務，而不是只回首頁。

## 成員流程

```mermaid
flowchart TD
  A[探索或收藏中找到群組] --> B[查看團主/價格/名額/規則]
  B --> C{符合申請條件}
  C -->|否| D[顯示不可申請原因或隱藏入口]
  C -->|是| E[檢查 PM 幣餘額]
  E -->|不足| F[儲值]
  E -->|足夠| G[填寫申請留言並同意規則]
  G --> H[送出申請]
  H --> I[我的訂閱顯示審核進行中]
  I --> J{團主審核結果}
  J -->|拒絕| K[收到通知並退款]
  J -->|通過| L[等待群組額滿或鎖定]
  L --> M[依服務機制填寫或提取帳號資訊]
  M --> N[等待團主啟用服務]
  N --> O[確認期檢查服務]
  O -->|正常| P[確認服務 可選擇評價]
  O -->|異常| Q[回報問題並附佐證]
  P --> R[服務進行中 等待續訂提醒]
  Q --> S[問題處理或申訴裁定]
```

主要入口：

- `/explore` 群組卡片
- `/favorites` 收藏群組
- 通知中心點擊申請結果或待處理通知
- `/my-subscriptions` 查看審核進行中、處理中、服務進行中與歷史紀錄

## 團主流程

```mermaid
flowchart TD
  A[建立群組] --> B[選擇服務]
  B --> C[選擇方案]
  C --> D[設定名額/門檻/規則]
  D --> E[預覽並送出]
  E --> F[群組進入招募中]
  F --> G[收到加入申請]
  G --> H{接受或拒絕}
  H -->|拒絕| I[退款給申請人]
  H -->|接受| J[建立成員資格]
  J --> K{是否額滿}
  K -->|否| F
  K -->|是| L[鎖定群組]
  L --> M[開啟聊天室並收集帳號資訊]
  M --> N{資訊是否齊全}
  N -->|否| M
  N -->|是| O[啟用服務並設定下次扣款日]
  O --> P[確認期處理成員回報]
  P --> Q[服務進行中查看收款與互動]
  Q --> R{到期決策}
  R -->|續訂| S[勾選續訂成員並收費]
  S --> L
  R -->|結束| T[群組結束並移入管理紀錄]
```

主要入口：

- 側邊欄或 Drawer 的「建立群組」
- `/manage-groups` 群組管理列表
- 通知中心的「新申請」「群組額滿」「成員資訊已填寫」「回報問題」等通知

## PM 幣與金流流程

```mermaid
flowchart LR
  A[使用者儲值] --> B[個人 PM 幣餘額]
  B -->|申請加入| C[群組代管餘額]
  C -->|取消申請| B
  C -->|申請被拒絕| B
  C -->|鎖定前退出或被移除| B
  C -->|群組解散| B
  C -->|確認期無異議或全員確認| D[團主餘額]
  C -->|申訴成立| B
  B -->|續訂收款| C
```

設計重點：

- 使用者看到的是「我付出的錢正在被平台代管」，不是直接付給團主。
- 任何退款、撥款、凍結都要跟群組狀態同步顯示，避免成員或團主對金流去向產生不信任。

## 申訴與客服流程

```mermaid
flowchart TD
  A[成員在確認期發現問題] --> B[提出問題回報並附佐證]
  B --> C[群組進入問題處理中 代管款項凍結]
  C --> D{團主是否能處理}
  D -->|能| E[團主標記處理完成]
  E --> F[回到確認期 重新讓成員確認]
  D -->|認定不實或無法處理| G[升級客服介入]
  C --> H[管理員查看申訴內容/附件/留言]
  G --> H
  H --> I{裁定結果}
  I -->|成員勝| J[該成員費用退款]
  I -->|團主勝| K[該筆費用不退款]
  J --> L[群組回到服務進行中或確認期後續狀態]
  K --> L
```

## 通知與訊息流程

```mermaid
flowchart LR
  A[業務事件成功] --> B[後端建立通知]
  B --> C[前端輪詢通知]
  C --> D[導覽顯示未讀數]
  D --> E[使用者打開通知中心]
  E --> F[依類型/群組/歷史篩選]
  F --> G[點擊通知]
  G --> H[標記已讀]
  H --> I[換頁並開啟對應 Modal 或面板]

  A --> J[若群組已鎖定或有私訊]
  J --> K[建立或更新對話]
  K --> L[訊息中心輪詢新訊息]
```

設計重點：

- 通知是任務入口，不只是紀錄。
- 訊息中心處理日常溝通；通知中心處理狀態變更與待辦。
- 對於會改變目前列表的事件，以提示加手動刷新為主，避免背景資料突然換掉造成認知中斷。

## 管理員流程

```mermaid
flowchart TD
  A[管理員登入] --> B[平台概覽]
  B --> C{處理類型}
  C -->|申訴| D[查看待裁定案件]
  D --> E[檢視申訴內容/佐證/雙方留言]
  E --> F[裁定團主勝或成員勝]
  F --> G[通知雙方並留下紀錄]
  C -->|平台回報| H[查看使用者回報]
  H --> I[必要時調整扣款日或標記處理]
  C -->|帳號| J[查詢帳號並恢復停用帳號]
  C -->|系統訊息| K[廣播或私訊通知使用者]
```

## 例外與復原路徑

| 情境 | UX 處理 |
|---|---|
| 群組卡片狀態過期 | 點開群組前重新查證；若已不可申請，提示重新整理或導回列表 |
| 申請時餘額不足 | 不開表單或阻止送出，引導儲值 PM 幣 |
| 申請被拒絕/取消 | 通知使用者、退回代管款項、保留再次探索路徑 |
| 群組鎖定前退出 | 顯示不可逆確認，成功後全額退款 |
| 成員逾期未填資料 | 群組轉進待處理狀態，不移除任何成員，團主可延長期限或協助處理 |
| 團主逾時未啟用 | 群組轉進啟用逾期狀態，不退回額滿，團主可補按啟用，成員也能提醒團主或回報問題 |
| 續訂時有人餘額不足 | 整批續訂失敗，團主看到不足名單 |
| 申訴進入客服介入 | 明確改變狀態文案，雙方知道已不再是一般確認期 |
