# 角色與使用者旅程

這份文件是 MVP 階段的設計假設，用於補齊 UI/UX 前期製作中的 persona、Jobs To Be Done 與 journey map。實際訪談或上線數據回收後，應再更新痛點優先級。

## 核心角色

| 角色 | 主要目標 | 主要擔心 | PartyMatch 需要提供 |
|---|---|---|---|
| 成員 | 用更低成本加入可靠的共享訂閱 | 被騙、付錢後拿不到服務、退費麻煩 | 清楚的團主資訊、PM 幣代管、狀態追蹤、問題回報 |
| 團主 | 快速補滿名額並降低管理成本 | 成員不付款、不填帳號、不續訂、爭議難處理 | 申請審核、代管確認、待辦提示、收款/續訂工具 |
| 管理員 | 維護平台信任與處理例外 | 缺少證據、裁定不透明、客服負擔過高 | 結構化申訴資料、附件、歷史紀錄、帳號/公告工具 |
| 訪客 | 判斷這個平台是否值得註冊 | 不知道流程是否安全、看不到足夠供給 | 免登入探索、清楚的價值說明、低壓力登入入口 |

## Persona

### Persona A：精打細算的訂閱成員

| 面向 | 說明 |
|---|---|
| 背景 | 有多個影音/音樂/AI 工具需求，但不想各自買完整方案 |
| 行為 | 會比較每月價格、團主評價、剩餘名額與共享方式 |
| 成功標準 | 能快速找到合適方案，付錢後有明確保障，服務啟用後能安心使用 |
| 風險感 | 最怕私下轉帳後被封鎖，或拿到不能用的帳號資訊 |
| UX 對策 | 群組卡片凸顯價格/名額/團主，申請時明確說明 PM 幣代管，確認期可申訴 |

### Persona B：穩定經營的團主

| 面向 | 說明 |
|---|---|
| 背景 | 自己已購買或準備購買家庭/團隊方案，希望分攤成本 |
| 行為 | 會設定信用門檻、挑選申請人、追蹤誰已填資料與誰需要提醒 |
| 成功標準 | 名額快速補滿、錢先被代管、續訂時不用重新手動對帳 |
| 風險感 | 擔心成員拖延、惡意申訴、或續訂前才發現有人不付款 |
| UX 對策 | 群組管理卡片顯示待辦、審核/鎖定/啟用分階段、續訂整批檢查餘額 |

### Persona C：處理例外的平台管理員

| 面向 | 說明 |
|---|---|
| 背景 | 平台維運者，需要處理申訴、帳號恢復、系統公告與平台回報 |
| 行為 | 先看逾期/待處理案件，再查證附件、留言與交易狀態 |
| 成功標準 | 用最少來回溝通完成公平裁定，並留下可追蹤紀錄 |
| 風險感 | 缺證據導致裁定不公，或誤動到非本案成員的金流 |
| UX 對策 | 後台提供申訴詳情、佐證附件、雙方留言、二選一裁定與結果通知 |

## Jobs To Be Done

| 情境 | Job |
|---|---|
| 想省訂閱費時 | 幫我快速比較可加入的群組，讓我知道哪個便宜又可靠 |
| 準備申請加入時 | 幫我確認付款與退費規則，讓我敢把錢交給平台代管 |
| 申請等待中 | 幫我知道現在卡在哪裡，以及我能不能取消 |
| 已加入但尚未啟用時 | 告訴我下一步要填什麼、何時截止、服務何時能用 |
| 服務有問題時 | 讓我能附證據回報，並知道錢暫時不會被撥走 |
| 開團招募時 | 幫我把服務方案、價格、規則講清楚，讓適合的人申請 |
| 審核申請時 | 幫我看到申請人的基本信任訊號，且不會超收名額 |
| 續訂前 | 幫我確認誰要續、誰餘額不足，避免扣款結果不一致 |

## 成員 Journey Map

| 階段 | 使用者目標 | 主要接觸點 | 可能情緒/風險 | UX 機會 |
|---|---|---|---|---|
| 發現 | 了解平台是否有自己需要的服務 | 首頁、探索頁、條件搜尋 | 好奇但不信任 | 在公開頁清楚呈現代管、安全與目前可加入群組 |
| 比較 | 找到價格、團主、名額都合適的群組 | 群組卡片、群組詳情、收藏 | 怕資訊不足 | 卡片保持掃描友善，詳情補足規則、評價、席位、費用 |
| 申請 | 送出申請並完成代管扣款 | 申請 Modal、PM 幣儲值 | 擔心扣款後沒保障 | 在送出前強調退款條件，餘額不足時提供直接儲值 |
| 等待 | 等團主審核或等群組額滿 | 我的訂閱、通知中心 | 不確定要不要做事 | 狀態文案明確區分審核中、已通過但等待額滿、等待鎖定 |
| 啟用前 | 填寫/提取服務帳號資訊 | 我的訂閱、群組詳情、訊息 | 怕填錯或錯過期限 | 依服務顯示正確欄位，錯誤不清空輸入，期限與完成狀態清楚 |
| 確認 | 確認服務是否能正常使用 | 確認期面板、問題回報 | 怕服務不能用但錢被撥走 | 保留回報入口、要求佐證、顯示代管凍結狀態 |
| 使用/續訂 | 持續使用並準備下一期 | 我的訂閱、續訂提醒、訊息 | 怕忘記儲值或錯過續訂 | 提前通知、顯示下次扣款日與餘額風險 |
| 收尾 | 群組結束後留評價或查看紀錄 | 訂閱紀錄、評價 Modal | 需要回顧歷史 | 歷史紀錄與評價入口保持可找 |

## 團主 Journey Map

| 階段 | 使用者目標 | 主要接觸點 | 可能情緒/風險 | UX 機會 |
|---|---|---|---|---|
| 建立 | 把可共享方案設定成可招募群組 | 建立群組 4 步驟 Modal | 擔心價格/名額填錯 | 服務與方案用目錄帶入，預覽卡片即時呈現 |
| 招募 | 找到適合成員並控管風險 | 探索曝光、群組管理、通知 | 怕亂申請或低信用成員 | 申請審核顯示申請留言、信用門檻與待辦數 |
| 額滿 | 將群組從招募推進到處理中 | 群組管理、鎖定 Modal | 怕鎖定太早或漏掉聊天室 | 額滿狀態凸顯「等待鎖定」主操作 |
| 收集資訊 | 確認成員提供的服務帳號或帳密提取狀態 | 帳號資訊面板、聊天室 | 怕有人拖延或填錯 | 顯示每位成員完成狀態，問題回報能要求修正 |
| 啟用 | 完成外部服務設定並確定扣款日 | 啟用服務 Modal | 怕日期/帳號錯導致爭議 | 啟用前摘要、下次扣款日必填、啟用後通知全員 |
| 確認期 | 處理成員確認或問題回報 | 問題處理面板、訊息 | 怕惡意申訴或錢卡住 | 問題回報與留言集中，必要時升級平台介入 |
| 服務中 | 維持服務、查看收款、準備續訂 | 收款明細、續訂 Modal | 怕有人不續或餘額不足 | 到期提醒、續訂成員勾選、整批餘額檢查 |
| 收尾 | 結束群組或進入下一期 | 管理紀錄、評價 | 希望留下可信紀錄 | 結束後保留歷史、引導互評 |

## 管理員 Journey Map

| 階段 | 使用者目標 | 主要接觸點 | UX 重點 |
|---|---|---|---|
| 監控 | 知道平台目前是否有待處理事件 | 後台概覽 | 統計與待處理數優先，而非大量明細 |
| 查證 | 針對申訴或平台回報取得完整上下文 | 申訴詳情、平台回報詳情 | 同頁呈現群組、成員、附件、留言與時間線 |
| 裁定 | 做出明確且可追蹤的決定 | 裁定操作 | 操作不可逆，需二次確認與理由 |
| 通知 | 讓受影響使用者知道結果 | 系統通知 | 文案要說明結果與下一步，而不只告知已處理 |
| 後續 | 查找歷史案件或恢復帳號 | 歷史紀錄、帳號管理 | 保留搜尋與追蹤能力 |

## 設計原則

- **狀態先於功能**：使用者最在意「現在輪到誰做什麼」，每個卡片/面板都要優先呈現目前狀態與下一步。
- **信任先於轉換**：涉及付款、帳號資訊、申訴時，文案與 UI 要讓使用者知道保障機制，不只催促行動。
- **角色可以重疊**：不要假設使用者只會是成員或只會是團主，導覽與通知要能同時服務兩種視角。
- **例外流程不能藏起來**：退款、退出、被拒絕、資訊有問題、申訴、逾期都要有清楚回饋，因為這些是信任感的關鍵時刻。
