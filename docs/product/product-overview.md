# 專案詳情

## PartyMatch 簡介

PartyMatch 是一個共享訂閱媒合平台，協助使用者一起分攤 Netflix、Spotify、YouTube Premium、Disney+ 等訂閱服務的費用。使用者可以在平台上尋找合適的合購群組，也可以自己建立群組成為團主；從找人、審核、付款代管、帳號資訊交付、服務確認，到後續續訂或爭議處理，都能在同一個流程裡完成。

## 動機＆解決困境

日常生活中，許多影音、音樂、AI 工具或雲端服務都有家庭方案或多人方案，但真的要找人一起合購時，流程往往很零散：可能是在 Facebook 社團發文、到 PTT 找人、用 Discord 私訊確認細節，再另外透過轉帳與截圖對帳。

這些方式雖然能湊成一團，卻也帶來不少不確定性。團主與成員多半互不認識，很難判斷對方是否可靠；付款紀錄散落在不同對話裡，事後不容易追蹤；帳號資訊交付、服務是否真的可用、有人臨時退出或發生糾紛時，也缺少一個共同認可的處理流程。

PartyMatch 希望把這些原本依賴私訊、截圖與口頭信任的步驟，整理成一套平台內流程。透過 PM 幣（平台內部代管餘額）進行付款代管，並搭配審核、服務確認、通知與申訴機制，讓合購訂閱不再只是「找到人一起付錢」，而是有狀態可追蹤、有紀錄可查、有爭議也能回到平台內處理。

## 使用者角色

- **成員**：探索與搜尋群組、申請加入、填寫服務帳號、追蹤訂閱狀態、儲值、提出申訴與留下評價
- **團主**：建立合購群組、審核申請、鎖定群組、提供或確認服務資訊、啟用服務、續訂或結束群組

一個使用者可以同時是某群組的團主，也是另一群組的成員。

## 核心使用者流程

探索群組 → 使用者送出申請（PM 幣進入平台代管）→ 團主審核 → 群組額滿後鎖定並開啟聊天室 → 團主提供或成員填寫帳號資訊 → 團主啟用服務 → 成員確認服務是否可正常使用 → 如有爭議可提出申訴 → 團主與成員互評 → 代管金額撥款至團主 PM 幣帳戶 → 進入續訂或結束流程

## 產品設計重點

PartyMatch 的設計重點，不是單純把合購流程做得「完整」，而是讓陌生人之間的合購能更接近一筆可被管理的交易。使用者不需要把信任全部押在對方的一句承諾上，也不用在多個聊天視窗裡追付款、追帳號、追截圖；平台會把關鍵節點收斂成清楚的狀態、紀錄與操作。

- **代管付款降低交易風險**：成員申請時先以 PM 幣進入平台代管，團主不會在尚未交付服務前收到款項；服務啟用並經成員確認後才撥款。取消申請、退出、被移除、群組解散或進入申訴時，也會依情境處理退款或凍結。
- **依服務情境引導帳號交付**：不同服務的共享方式差異很大，有些需要家庭邀請，有些用 Email 加入，有些則是共用帳密。PartyMatch 會依服務類型顯示對應欄位與說明，避免團主和成員在私訊裡反覆確認「到底要給什麼資料」。
- **敏感資訊依角色揭露**：共用帳密、成員服務帳號與申訴附件不只是前端隱藏，而是依團主、成員、申請者與訪客的身分，以及群組目前所在階段動態遮罩；需要保護的內容也會加密或私有化處理。
- **爭議處理保留上下文**：如果成員遇到帳號無法登入、服務無法使用或團主未如期處理，可以在平台內回報並附上佐證。後續若需要管理員介入，也能看到群組、成員、附件、留言與交易紀錄，而不是只根據零散截圖判斷。
- **信用與行為紀錄輔助篩選**：信用分數會依使用者在平台內的行為調整，例如是否準時完成帳號資訊、是否頻繁退出或是否正常完成合購流程。團主可以設定申請門檻，平台也能透過冷卻期與扣分降低惡意或反覆違約的成本。
- **通知與訊息集中管理**：合購過程中的審核、提醒、帳號資訊、服務確認、續訂與申訴，都會透過群組聊天室、私訊與通知中心串起來，讓使用者不必在不同頁面之間猜現在輪到誰處理。

## 目前狀態

MVP 階段，核心流程皆已實作。PM 幣代管與付款目前為平台內模擬邏輯，尚未接上真實金流；訊息與通知採 polling，而非即時推播。
